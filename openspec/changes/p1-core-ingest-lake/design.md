## Context

P0 delivered an empty typed package, CI, and `corpus-v1`. This change builds the ingest core: raw store, ledger, wpilog decoding, hoot conversion, log metadata, and bronze samples. Decisions in play: D1 (Parquet + DuckDB), D2 (Polars), D3 (wpilog reader), D4 (owlet registry). All four are still Proposed ADRs; this design revises D3 and refines D1 and D4 based on the measurements below.

### Spike results (2026-10-04, Apple Silicon, corpus `2026-gacmp-q7`)

| Measurement | Value |
|---|---|
| System wpilog: 23 MB, 643 K records, 565 entries | Python per-record reader: 0.7 s |
| CANivore hoot → wpilog, all signals (owlet 26.1.0) | 6.4 s → 599 MB, **36.9 M records**, 1,021 signals |
| Same, read with the official reader (Python bindings, one Python call per record) | **36 s**, ~1 M records/s |
| Same, read with a compiled scanner (numba, spec-based) | **0.86 s warm / 1.6 s cold**, record count identical to the official reader |
| CANivore hoot, `health` profile (212 signals via `owlet -s`) | owlet 3.4 s → 162 MB, 10.3 M records, scan 0.3 s |
| Parquet (zstd-3) of double samples, all / health | 126 MB / 44 MB per bus per match; one-signal read 5 ms |
| Records in timestamp order? | **No** (both files) |

Other facts:
- The hoot compliancy byte is at file offset 70. This matches the `--compliancy` output on every corpus hoot, and it is how AdvantageScope selects owlet.
- CTRE publishes `https://redist.ctr-electronics.com/index.json`. It lists owlet versions per compliancy, with URLs and SHA-1 for `macosuniversal`, `linuxx86-64`, `linuxarm64`, and `windowsx86-64`.

## Goals / Non-Goals

**Goals:**
- `flashpoint ingest PATH...` turns corpus logs into raw, bronze, and metadata outputs, idempotently, within the budget (under 30 s, under 1 GB per match).
- Per-file failures quarantine the file without aborting the run.
- `flashpoint doctor` reports environment health (owlet cache, lake location, versions).

**Non-Goals:**
- Decoding struct, array, or protobuf payloads into fields. They are stored losslessly as raw bytes, and decoding comes later.
- Mapping to robots, slots, or units. Match identity resolution. Silver and gold layers. (All P2.)
- REV and Driver Station logs.

## Decisions

### D3 revised: compiled spec-based scanner; the official reader becomes the test oracle
The official reader is fast in C++, but crossing into Python once per record caps throughput at about 1 M records/s. All-signals hoot exports would then blow the budget, and even `health` exports would use about a third of it.
- Implement the WPILib DataLog 1.0 record framing as a numba-compiled scan over a memory-mapped file. It returns parallel arrays (entry id, timestamp, payload offset, payload size).
- Decode control records (Start, Finish, SetMetadata) in Python. There are few of them.
- Gather typed values with compiled per-type kernels.
- `robotpy-wpiutil` stays as a **dev dependency** and is used as the oracle in equivalence tests.
- Update ADR-0003.
- *Alternatives:* the official reader (36 s for one bus); a Rust or C extension (fastest, but a build toolchain burden for students); `owlet` to MCAP plus an MCAP reader (still per-message Python).
- *Risk:* numba's first-run JIT takes about 1 s per kernel. Mitigated by `cache=True`, and by excluding warm-up from the budget (spec). numba wheels exist for every target platform.

### D4 refined: owlet registry sourced from CTRE's redist index
- `src/flashpoint/readers/owlet-manifest.toml` is committed. It is generated by `tools/update-owlet-manifest.py` from CTRE's index, taking stable channels only and the latest version per compliancy.
- Each manifest row holds compliancy, version, and per-platform url, sha1 (from CTRE), and sha256 (computed when the manifest is generated).
- Platform keys: `macosuniversal`, `linuxx86-64`, `linuxarm64`, `windowsx86-64`.
- Binaries are cached at `~/.cache/flashpoint/owlet/owlet-<version>-C<n>[.exe]`, and their sha256 is verified on every use.
- Compliancy is read from **byte 70** of the hoot, so no subprocess is needed to probe. If the file is shorter than 72 bytes, the reason is `empty-file` (0 bytes) or `invalid-header`. A compliancy below 6 is quarantined as too old.
- **Signal profiles:**
  - Run `owlet --scan` (cached per compliancy and file) to list `name: id` pairs.
  - The `health` profile is a regex allowlist over signal names, matching what the spike used: voltages, currents, temperatures, velocity, position, duty cycle, enable state, faults, version, robot enable and mode.
  - Pass the matching ids with `-s`. The `all` profile omits `-s`.
- **Pro flag:** run `owlet --check-pro`, and parse "is Pro-licensed".
- **Conversion parallelism:** hoots in one ingest run convert concurrently, bounded by CPU count.

### Integrity check for truncated hoots
owlet converts truncated hoots without error. After bronze is written, compare each hoot's last sample timestamp (wall-clock anchored) to the session end of any wpilog it overlaps. If the hoot ends more than 20 % of the overlap window early, mark it `short-coverage`. A hoot with no overlapping wpilog skips the check, and that is recorded.

### D1 refined: ledger in SQLite (WAL), samples in Parquet
The ledger needs transactional per-file state changes, and Parquet is the wrong tool for mutable rows.
- `lake/meta/flashpoint.sqlite` (WAL mode) holds the `files`, `aliases`, `logs`, `hoot_logs`, `entries`, and `inventory` tables.
- After each run, the tables are exported to `lake/meta/*.parquet` snapshots, so DuckDB can query everything without extensions (it stays offline-safe).
- Update ADR-0001's layout note.

### Lake layout and atomic writes
```
$FLASHPOINT_LAKE (default ~/flashpoint-lake)
  raw/<sha256[:2]>/<sha256>.<ext>
  bronze/samples/season=<YYYY|unknown>/log_id=<sha256>/part-0.parquet
  bronze/_staging/<run-id>/...          # same filesystem; renamed into place
  meta/flashpoint.sqlite  meta/*.parquet
```
- Bronze is written to `_staging`, `fsync`ed, then moved into place with an atomic directory rename. Only after that does the ledger move the file to `success`.
- Leftover staging directories are deleted at the start of each run.
- **Bronze columns:** `signal` (dictionary-encoded string), `type` (dictionary), `ts_us` (int64), `v_f64`, `v_i64`, `v_bool`, `v_str`, and `v_bytes` (nullable). The data is sorted by `(signal, ts_us)` within the file, which gives good row-group statistics and solves the unordered-timestamp problem.
- **Season** comes from the anchored UTC start year. The filename is the fallback, then `unknown`.

### Metadata extraction
- FMS fields come from `NT:/FMSInfo/*` (the last non-empty value).
- Build metadata is parsed from the `MetaData` string entries (`Key: Value`, split on the **first** `": "` only; fixes #16).
- The wall-clock anchor is a linear fit of `systemTime` value against the record timestamp. With no `systemTime`, the filename timestamp is used.
- `/Flashpoint/CANInventory` payloads are stored verbatim and validated against schema v1.

### Pipeline version
`flashpoint.PIPELINE_VERSION` is an integer bumped whenever bronze or metadata output changes. `flashpoint rebuild` reprocesses older files from raw storage.

### CLI
`flashpoint ingest [--lake DIR] [--profile health|all] [--jobs N] PATH...` (files or directories, searched recursively), `flashpoint rebuild`, and `flashpoint doctor`. Exit code 0 means all files succeeded; 1 means any file was quarantined; 2 means a usage or environment error.

## Risks / Trade-offs

- **numba is a heavy dependency (llvmlite).** It is acceptable for a pit laptop. If it ever blocks a platform, the scanner's interface allows a pure-Python fallback (slow, but correct).
- **The CTRE index format may change.** The manifest is generated offline and committed, so ingest never depends on the index at runtime. Only `update-owlet-manifest.py` does.
- **The `health` allowlist may miss a signal needed later.** Raw hoots are kept, so a profile change plus `rebuild` recovers it.
- **SQLite ledger and DuckDB analytics are two engines.** The Parquet snapshots keep the analytics side single-engine.
- **Lake size:** about 100 MB per match with the `health` profile (two buses plus the system log), plus raw files. That is about 10–15 GB per season, which is acceptable on a laptop. `all` is about 3× larger.
